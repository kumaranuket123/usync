# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Usync is a Flutter app (Android + iOS, portrait-only) for realtime emotional connection between couples: shared drawing canvas, touch sync, mood sharing, memories, timeline. Backend is Firebase project `usync-app`.

## Commands

Flutter version is pinned via FVM (`.fvmrc`, 3.41.9), so prefix with `fvm` if it is installed.

- `flutter pub get` — install deps
- `flutter run` — run on a device/emulator
- `flutter analyze` — lint (uses `flutter_lints`; `android/`, `ios/`, `build/` excluded)
- `flutter test` / `flutter test path/to/file_test.dart` — there is currently no `test/` directory

Firebase rules live in `firestore.rules` and `database.rules.json` (deployed with `firebase deploy --only firestore:rules,database`). `lib/firebase_options.dart` is generated by FlutterFire.

## Architecture

Clean-architecture layering under `lib/`, BLoC for state, GetIt for DI, go_router for navigation:

- `domain/` — entities and `I*Repository` interfaces (auth, couple, mood, memory, canvas, touch, notification).
- `data/` — `datasources/remote/` (`FirestoreSource`, `RtdbSource`, `FirebaseAuthSource`), `datasources/local/` (Hive, SharedPreferences), `models/` (serialization to/from entities), `repositories/` (implementations).
- `presentation/features/<feature>/{bloc,screens}` — one folder per feature; `presentation/shared/` holds reusable widgets, custom painters, and animations.
- `core/` — DI, router, theme, constants, extensions, utils.

### Wiring a new feature
1. Add the interface in `domain/repositories`, implement in `data/repositories`.
2. Register the repository (lazy singleton, bound to the interface) and the BLoC (**factory**) in `core/di/injection.dart`. `setupLocator()` runs in `main()` after Firebase/Hive init.
3. Add the route in `core/router/app_router.dart` (path constant in `core/constants/route_names.dart`). Main tabs go inside the `ShellRoute` (`UsyncShell` bottom nav); pre-auth and pairing routes are outside it.
4. Screens obtain BLoCs via `GetIt.I<...>()` inside `BlocProvider`; only `AuthBloc`, `SettingsBloc`, `ThemeBloc` are provided app-wide in `app.dart`.

### Auth / routing
`RouteGuards.redirect` reads `FirebaseAuth.instance.currentUser` directly: unauthenticated users are limited to splash/onboarding/login/register; authenticated users are bounced off those to home. Pairing routes are always reachable. `app.dart` additionally routes to login when `AuthBloc` emits `Unauthenticated`.

### Data split: Firestore vs Realtime Database
- **Firestore** (durable data): `users`, `couples`, `inviteCodes`, `moods/{coupleId}/history`, `memories/{coupleId}/items`, `milestones/{coupleId}/events`, `notifications/{coupleId}/items`.
- **RTDB** (ephemeral/low-latency, all keyed by `coupleId`): `presence`, `mood/.../current`, `canvas` (strokes, points, `clearedAt`), `touch` (uses `onDisconnect` to clear state).
- Everything is scoped by `coupleId`; Firestore rules check membership via `couples/{id}.userAId/userBId`. Note `database.rules.json` currently only requires `auth != null`.

### Theming
Five selectable themes in `core/theme/themes/` (midnight_purple, lavender_dream, sunset_glow, ocean_blue, neon_pink) built on `UsyncThemeData`; `ThemeBloc` persists the choice via prefs and exposes `themeData`. Prefer theme/`app_colors`/`app_text_styles` over hard-coded styles.

### Other
- FCM token is requested and saved in `main.dart` (`_initFcm`) via `IAuthRepository.updateFcmToken`.
- Per-feature specs are in `docs/features/*.md`; `design/index.html` is the design reference.
