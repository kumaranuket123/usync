# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Usync is a Flutter app (Android + iOS, portrait-only) for realtime emotional connection between couples: shared drawing canvas, touch sync, mood sharing, memories, timeline. Backend is Supabase project `usync` (`omatuaemysgykmdgsqvr`); Firebase is kept only for FCM push delivery.

## Commands

Flutter version is pinned via FVM (`.fvmrc`, 3.41.9), so prefix with `fvm` if it is installed.

- `flutter pub get` — install deps
- `flutter run` — run on a device/emulator
- `flutter analyze` — lint (uses `flutter_lints`; `android/`, `ios/`, `build/` excluded)
- `flutter test` / `flutter test path/to/file_test.dart` — there is currently no `test/` directory

Supabase schema + RLS live in `supabase/schema.sql`; later changes are in `supabase/migrations/` and are applied to the project as migrations. The push Edge Function is `supabase/functions/send-push/` (needs the `FCM_SERVICE_ACCOUNT` secret set in the Supabase dashboard). `lib/firebase_options.dart` is generated by FlutterFire and is only used for FCM.

## Architecture

Clean-architecture layering under `lib/`, BLoC for state, GetIt for DI, go_router for navigation:

- `domain/` — entities and `I*Repository` interfaces (auth, couple, mood, memory, canvas, touch, notification).
- `data/` — `datasources/remote/` (`SupabaseAuthSource`, `CoupleChannelSource`, `StorageSource`; repositories also use the `SupabaseClient` directly), `datasources/local/` (Hive, SharedPreferences), `models/` (serialization to/from entities), `repositories/` (implementations).
- `presentation/features/<feature>/{bloc,screens}` — one folder per feature; `presentation/shared/` holds reusable widgets, custom painters, and animations.
- `core/` — DI, router, theme, constants, extensions, utils.

### Wiring a new feature
1. Add the interface in `domain/repositories`, implement in `data/repositories`.
2. Register the repository (lazy singleton, bound to the interface) and the BLoC (**factory**) in `core/di/injection.dart`. `setupLocator()` runs in `main()` after Firebase (FCM only), Supabase and Hive init.
3. Add the route in `core/router/app_router.dart` (path constant in `core/constants/route_names.dart`). Main tabs go inside the `ShellRoute` (`UsyncShell` bottom nav); pre-auth and pairing routes are outside it.
4. Screens obtain BLoCs via `GetIt.I<...>()` inside `BlocProvider`; only `AuthBloc`, `SettingsBloc`, `ThemeBloc` are provided app-wide in `app.dart`.

### Auth / routing
`RouteGuards.redirect` reads `Supabase.instance.client.auth.currentUser` directly: unauthenticated users are limited to splash/onboarding/login; authenticated users are bounced off those to home. Pairing routes are always reachable. `app.dart` additionally routes to login when `AuthBloc` emits `Unauthenticated`. Sign-in is Google only (`google_sign_in` native picker -> `signInWithIdToken`; client IDs in `core/constants/google_config.dart`); the first sign-in creates the user and the `handle_new_user` trigger creates the `profiles` row from the Google name.

### Data split: Postgres vs Realtime channel
- **Postgres tables** (durable, all scoped by `couple_id`, protected by RLS using `is_couple_member` / `is_active_couple_member`): `profiles`, `device_tokens`, `couples`, `invite_codes`, `moods`, `memories`, `milestones`, `notifications`, `canvas_strokes`. The "current" partner mood is the latest `moods` row.
- **Couple state changes go through RPCs**, not direct writes: `join_with_code`, `disconnect_couple` (either partner can disconnect on their own, no confirmation).
- **Realtime**: one private channel `couple:<id>` (`CoupleChannelSource`) carries Presence (online), Broadcast touch events and live canvas stroke chunks; finished strokes are persisted to `canvas_strokes`. Channel access is enforced by policies on `realtime.messages`. There is no `onDisconnect`: touch ends when the partner's Presence leaves.
- **Storage**: private `memories` bucket, objects at `<couple_id>/<uuid>.png`; `memories.thumbnail_url` stores the path and the repository swaps in signed URLs.
- **Push**: inserting a `notifications` row fires the `notify_push` trigger -> `send-push` Edge Function -> FCM to the partner's `device_tokens` row.

### Theming
Five selectable themes in `core/theme/themes/` (midnight_purple, lavender_dream, sunset_glow, ocean_blue, neon_pink) built on `UsyncThemeData`; `ThemeBloc` persists the choice via prefs and exposes `themeData`. Prefer theme/`app_colors`/`app_text_styles` over hard-coded styles.

### Other
- FCM permission, token saving and foreground/tap handling live in `core/services/push_notification_service.dart` (`PushNotificationService.init()` from `main.dart`); the token is upserted into `device_tokens` via `IAuthRepository.updateFcmToken`.
- Per-feature specs are in `docs/features/*.md`; `design/index.html` is the design reference.
